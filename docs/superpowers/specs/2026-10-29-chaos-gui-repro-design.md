## 이번 범위

1. **테스트 전용 결함 주입**: WorkerLauncher/run_batch의 실제 OS 프로세스를 사용하되 테스트 전용 워커의 비정상 종료(결과 JSON 누락), 결과 JSON 오염, CSV 손상 및 디스크 쓰기 오류를 주입. 정상 서버의 CSV와 latest.csv 보호, 3슬롯 제한, 배치 요약 상태, 중단 마커 정리를 검증한다.
2. **실제 Tk 위젯 검증**: Windows CI에서 사용자 입력 항목의 미저장 값이 반복 refresh에도 유지되고 3대 서버 등록 제한·목록 선택이 유지되는지 실제 tkinter 창의 위젯으로 확인한다. 테스트 데이터/경로만 사용하며 계정·AirWave 접속 금지.
3. **빌드 재현성**: 현재 통과한 Python 3.12 CI 직접 패키지 버전을 constraints로 고정하고, 빌드 환경의 의존성 정보를 CI 아티팩트로 기록한다. 애플리케이션 배포용 pyproject 최소/상한 범위와 실행 동작은 변경하지 않는다.
4. **장시간 측정 범위 보존**: 기존 수동 5/30/120/240분과 로컬 Windows 480분 명령·보고 형식 유지. 실제 장시간 실행은 검증 결과가 없으면 완료라고 주장하지 않는다.

## 엄격한 비변경 계약

기존 Windows 11 GUI 버튼·문구·CLI 옵션, 최대 5대 등록, 기본 3대 병렬, 180초 재시도, 15~30초 Devices 목록 대기, 저장 경로/CSV 형식·파일명, Windows 예약 작업 1개, Windows Credential Manager 자격 증명 보호 유지. 테스트 전용 결함 주입 파라미터를 운영 코드 또는 EXE에 노출하지 않는다.

## 선택한 구현 접근법

A. 운영 코드에 테스트용 fail/crash 플래그 추가: 사용자 기능 동결·보안에 악영향 → 제외.
B. 이미 존재하는 `tests/support/synthetic_worker.py`에만 모의 장애 트리거 추가하고, 프로덕션 `run_batch`와 `WorkerLauncher`는 변경 없이 검증 → **선택**.
C. 전부 Mock 객체만으로 검증: 실제 OS 프로세스와 JSON 결과 손상에 대한 증거 부족 → 보조만 허용.
